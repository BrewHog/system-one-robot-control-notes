Reproducing all of this

2026-09-18 · in order, from a clean machine

Every number in these notes came from the commands below. If you want to check my work, this is the whole path. Nothing here needs my API key except the System 1 steps, and those are clearly marked.

Requirements

Docker, runningfor the simulated robot

1. Bring up the simulated robot

cd /Users/justin/workspaces/Contoro_and_JEV
./scripts/start_sim.sh

First run builds a native arm64 ROS 2 Jazzy image. The script frees ports, starts the container, and waits for rosbridge. It prints a VNC address (vnc://localhost:5900) if you want to watch the robot, which is pleasant but, as note 05 explains, not evidence of anything.

2. Prove the simulator is reachable

.venv/bin/python scripts/probe_rosbridge.py --port 9090

Expected: ROS version 2 (jazzy), 7 topics, >50 services, and OK: simulator is reachable. If topics come back empty, you have the rosapi discovery problem from note 05.

3. Prove an MCP client can drive it

.venv/bin/python scripts/mcp_e2e_test.py --port 9090

Spawns ros-mcp over stdio, lists its tools, drives the turtle, and verifies motion through a second independent rosbridge connection. Expected: 31 tools and PASS: MCP client drove the simulated robot through ros-mcp. No API key needed — this is the pure transport check.

4. Measure the System 1 round trip (needs a key)

export TYPESAFE_API_KEY=...
.venv/bin/python scripts/jev_smoke.py

Prints the wall-clock round trip for a three-question call. My measurement was 252 ms on a cold connection; see note 03 for why that number is the pessimistic end.

5. Run the open loop, to confirm state actually reaches the model

.venv/bin/python scripts/jev_discriminate.py

Asks the same question against deliberately opposite robot states and reports whether the answers separate. This exists because a System 1 layer that returns the same answer regardless of input would look fine in a control loop while doing nothing useful — and it is the cheapest possible check against that.

6. Run the closed loop

# scripted baseline, no model in the loop
.venv/bin/python scripts/jev_controller.py --ticks 12 --no-jev

# with the System 1 model judging each tick
.venv/bin/python scripts/jev_controller.py --ticks 12 --hold 0.9

Each run writes a decision log to logs/jev_run_<epoch>.json containing, per tick: the pose, the full structured state sent to the model, the raw answers, and the resulting command. That log is what made the diagnosis in note 04 possible, so it is worth reading rather than discarding.

Expect the shipped control law to limit-cycle. That is the reproducible result, not a setup error on your side.

7. Reproduce the control-law diagnosis

.venv/bin/python scripts/control_law_diagnosis.py --ticks 10 --hold 0.9

Resets the simulator to a known pose, replays the shipped control law and a rate-limited variant against the identical start, and writes logs/control_law_diagnosis.json with a per-step error and distance trace.

That script now refuses to print a success verdict unless the variant shows sustained net progress the shipped law did not. I added that guard after it initially reported a fix on the strength of total displacement alone, while the heading error was still oscillating. Changing a test so that it is allowed to fail is the part of this project I would most recommend copying.

Verifying the artifacts themselves

To confirm these files are the ones I published, check them against the manifest:

sha256sum -c manifest.txt      # Linux
shasum -a 256 -c manifest.txt  # macOS

Every file listed is hashed. manifest.txt.ots is an OpenTimestamps proof anchoring the manifest to the Bitcoin blockchain, and manifest.tsr is an independent RFC 3161 timestamp token. See note 07 for what those prove and what they do not.

What you cannot reproduce

Stated so the limits are clear:

  • My exact latency figures. They are network-dependent and will differ on your machine and at your distance from the API.
  • turtlesim's exact trajectory, which depends on real-time scheduling and will vary run to run. The failure is reproducible; the specific centimetres are not.
  • The timestamps. Those are the point of the proof bundle and are tied to one moment.
